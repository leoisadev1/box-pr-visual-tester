Visual QA for Every Pull Request with Upstash Box Browser

Leo@leodev | October 28, 2026 | 9 min read
boxaibrowsergithubplaywrighttesting

I run several coding agents in parallel across Git worktrees. When an agent finishes a task in its worktree and opens a pull request, tsc and the test suite are already green in the terminal. What the agent does not check by default is how the change renders in a real browser across mobile and desktop viewports compared to main.

A two-line CSS change in a dialog can push the submit button below the fold on a phone screen while every unit test still passes. Even with separate worktrees ready on disk, reviewing ten pull requests by hand means starting two dev servers on different ports, opening both in a browser, resizing DevTools to a mobile viewport, and clicking through the flow yourself.

I wanted every pull request on GitHub to get that before-and-after browser check automatically. When you pass browser: true to Upstash Box, the container boots with a managed Chromium instance next to its shell, filesystem, Git checkout, and coding agent. A single Box can restore from a warm snapshot, run main on :3000 and the pull request branch on :3001, inspect both in Chromium, upload screenshots to Upstash Blob, and post a visual review comment on the pull request.

Visual QA options in Upstash Box Browser

Enabling browser: true on Box.create or Box.fromSnapshot gives you five ways to drive Chromium and inspect a live page. All of them operate on the same browser instance inside the Box, so you can use one or combine them in a single test run.

Capability SDK call Best for
AI actions and zero-LLM replay tab.act("...") and tab.observe("...") Clicking buttons or stepping through flows described in plain English, then replaying the resolved selector without an LLM
Schema-validated extraction tab.extract(prompt, zodSchema) and tab.content() Asking a DOM-aware agent structured questions about the rendered page and getting back typed Zod data
Screenshots, video, and live view tab.screenshot(), box.browser.recordings.start(), and tab.liveViewUrl() Capturing viewport or full-page PNGs, recording MP4 session videos, or streaming a live view URL
Playwright or Puppeteer over CDP await box.browser.cdpUrl() Attaching playwright-core to the same tab for exact viewport sizing and getBoundingClientRect() layout math
In-box coding agent box.agent.run({ prompt, responseSchema }) Running Claude Code, Codex, or OpenCode inside the Box with the chrome-devtools MCP wired in

Here is how those calls work together on a single tab:

src/box-stages.tstypescript
import { Agent, Box, BoxApiKey, ClaudeCode } from "@upstash/box";
import { z } from "zod";

const box = await Box.create({
  runtime: "node",
  browser: true,
  agent: {
    harness: Agent.ClaudeCode,
    model: ClaudeCode.Sonnet_4_5,
    apiKey: BoxApiKey.UpstashKey,
  },
});

// 1. Open a tab against the app running on the Box's own localhost
const tab = await box.browser.tab.create("http://localhost:3000/billing/", {
  waitUntil: "networkidle",
});

// 2. Trigger UI state in plain English, or resolve once with tab.observe and replay
const { elements } = await tab.observe("the Upgrade Plan button");
if (elements[0]?.selector) {
  await tab.act(elements[0]); // deterministic replay: no LLM call, zero tokens
} else {
  await tab.act("Click the Upgrade Plan button");
}

// 3. Extract Zod-validated state from the live DOM
const dialogState = await tab.extract(
  "Read the checkout dialog. Return the primary button's label and the validation message under the cardholder name, or null if there is none.",
  z.object({
    primaryButtonLabel: z.string(),
    validationMessage: z.string().nullable(),
  }),
);

// 4. Capture a PNG screenshot, or record MP4 video with box.browser.recordings.start
const png = await tab.screenshot({ fullPage: false });

Because box.browser.tab.create() and box.browser.cdpUrl() point to the same Chromium process, a tab opened through the Box SDK is immediately visible to Playwright over CDP.

In our pull request tester, tab.act() opens the checkout modal, Playwright resizes the tab to 390x844 mobile and 1440x900 desktop viewports to measure the submit button's exact pixel coordinates, tab.extract() reads the rendered dialog state, and tab.screenshot() captures the annotated before-and-after PNGs.

The bug that terminal checks miss

On the /billing/ page of our demo app, clicking Upgrade Plan opens the #checkout modal. On main, the #checkout container uses fixed inset-x-4 top-12 without a height cap or scroll container, and the footer uses a static <div class="modal-foot">.

On a 390x844 mobile viewport, the modal overflows the screen on main and pushes the Confirm upgrade button below the bottom edge:

On main at 390x844, getBoundingClientRect() on #confirm reports top: 861.5px and bottom: 910px. The button ends 66px below the 844px fold with 0% of the button visible on screen, so attempting to submit the form times out.

Pull request #1 fixes the modal in app/billing/index.html with two class updates:

app/billing/index.htmldiff

+ <div id="checkout" class="modal fixed inset-x-4 top-12 max-h-[85dvh] overflow-y-auto" role="dialog" aria-modal="true" aria-labelledby="checkout-title" hidden>
...
- <div class="modal-foot">
+ <div class="modal-foot sticky bottom-0">

With that change, the button moves up to top: 696.9px and bottom: 745.4px, leaving 98.6px of room above the 844px mobile fold. Submitting with an empty cardholder name renders "Enter the name on your card." while keeping 100% of the button visible.

Step 1. Pre-warm a Box snapshot once

Installing npm dependencies from scratch on every pull request adds unnecessary wait time. Instead, we create a seed Box with browser: true, clone the repository once, warm the npm cache with npm ci, and save the container state with seed.snapshot().

src/box-stages.tstypescript
import { Agent, Box, BoxApiKey, ClaudeCode } from "@upstash/box";

export async function createBaseSnapshot(repoUrl: string): Promise<string> {
  const seed = await Box.create({
    runtime: "node",
    size: "small",
    browser: true,
    agent: {
      harness: Agent.ClaudeCode,
      model: ClaudeCode.Sonnet_4_5,
      apiKey: process.env.ANTHROPIC_API_KEY ?? BoxApiKey.UpstashKey,
    },
    git: { token: process.env.GITHUB_TOKEN! },
  });

  try {
    await seed.git.clone({ repo: repoUrl, folder: "seed", depth: 1 });
    await seed.cd("seed");
    await seed.exec.command("npm ci --no-audit --no-fund");

    const snapshot = await seed.snapshot({ name: "pr-visual-base" });
    return snapshot.id;
  } finally {
    await seed.delete();
  }
}

Step 2. Restore the Box and boot main and the PR side by side

When a pull request opens or updates, Box.fromSnapshot() restores a fresh container from that snapshot. Inside the Box, we clone the base branch into /workspace/box/main on port 3000 and the pull request branch into /workspace/box/pr on port 3001. Both checkouts pin the exact commit SHAs from the pull request event.

src/box-stages.tstypescript
export const BRANCHES = [
  { key: "before", folder: "main", port: 3000 },
  { key: "after", folder: "pr", port: 3001 },
] as const;

const box = await Box.fromSnapshot(process.env.BOX_SNAPSHOT_ID!, {
  size: "small",
  browser: true,
  keepAlive: false,
  agent: {
    harness: Agent.ClaudeCode,
    model: ClaudeCode.Sonnet_4_5,
    apiKey: process.env.ANTHROPIC_API_KEY ?? BoxApiKey.UpstashKey,
  },
  git: { token: process.env.GITHUB_TOKEN! },
});

for (const branch of BRANCHES) {
  const isHead = branch.key === "after";
  const sha = isHead ? pr.headSha : pr.baseSha;

  await box.git.clone({
    repo: isHead ? pr.headCloneUrl : pr.baseCloneUrl,
    branch: isHead ? pr.headRef : pr.baseRef,
    folder: branch.folder,
    depth: 1,
  });

  await box.cd(branch.folder);
  await box.exec.command(`git fetch --depth 1 origin ${sha} && git checkout --detach ${sha}`);
  await box.exec.command("npm ci --prefer-offline --no-audit --no-fund");
  await box.exec.command(`PORT=${branch.port} nohup npm start > /tmp/${branch.folder}.log 2>&1 &`);
  await box.cd("..");
}

Running both branches inside the same Box eliminates clock skew, font differences, and network jitter between the baseline and the pull request preview.

Step 3. Inspect both branches with Box Browser

Once localhost:3000 and localhost:3001 respond, inspectPreviews() connects to the Box's Chromium instance. Each branch is opened with box.browser.tab.create(), clicked with tab.act(), measured at 390x844 and 1440x900 over box.browser.cdpUrl(), cross-checked with tab.extract(), and captured with tab.screenshot().

src/box-stages.tstypescript
import { chromium, type Browser } from "playwright-core";
import { z } from "zod";
import { annotate, inspectCheckout, VIEWPORTS } from "./probe.js";

export const AgentRead = z.object({
  primaryButtonLabel: z.string(),
  validationMessage: z.string().nullable(),
});

async function inspectBranch(box: Box, browser: Browser, url: string, label: string) {
  const tab = await box.browser.tab.create(url, { waitUntil: "networkidle" });
  const page = browser.contexts().flatMap((c) => c.pages()).find((p) => p.url().startsWith(url))!;

  const openCheckout = async () => {
    const action = await tab.act("Click the Upgrade Plan button");
    if (!action.success) await page.getByRole("button", { name: "Upgrade Plan" }).click();
  };

  const shots: Record<string, Uint8Array> = {};
  const reports: Record<string, unknown> = {};

  for (const viewport of VIEWPORTS) {
    const cdp = await page.context().newCDPSession(page);
    await cdp.send("Emulation.setDeviceMetricsOverride", {
      width: viewport.width,
      height: viewport.height,
      deviceScaleFactor: 2,
      mobile: viewport.name === "mobile",
    });

    const report = await inspectCheckout({ page, viewport, openCheckout });
    await annotate(page, report);
    shots[viewport.name] = await tab.screenshot();
    reports[viewport.name] = report;
    await cdp.detach();
  }

  const agentRead = await tab.extract(
    "Read the checkout dialog. Return the primary button's label and the validation message under the cardholder name, or null if there is none.",
    AgentRead,
  );

  await tab.close();
  return { run: { label, reports }, shots, agentRead };
}

Step 4. Generate a typed verdict with box.agent.run and upload screenshots to Upstash Blob

With the four screenshots and viewport measurements collected, we call box.agent.run() with a Zod responseSchema. Claude Code runs inside the Box, compares the base branch metrics against the pull request metrics along with the tab.extract() output, and returns a validated Verdict object.

src/report.ts & src/box-stages.tstypescript
import { Bucket } from "@upstash/blob";
import { z } from "zod";

export const VerdictSchema = z.object({
  status: z.enum(["pass", "fail"]),
  headline: z.string().describe("One sentence, under 90 characters."),
  summary: z.string().describe("Two or three sentences a reviewer can act on."),
  regressions: z.array(z.string()).describe("Problems the PR introduces. Empty when there are none."),
});

const run = await box.agent.run({
  prompt: buildVerdictPrompt({ prNumber: pr.number, title: pr.title, before, after, agentRead }),
  responseSchema: VerdictSchema,
  timeout: 120_000,
});

const bucket = new Bucket({ token: process.env.UPSTASH_BLOB_TOKEN! });
const blob = await bucket.put(
  `visual-qa/${pr.repo}/pr-${pr.number}/${pr.headSha}/after-mobile.png`,
  shots.after.mobile,
  { contentType: "image/png", cache: "immutable" },
);

Step 5. Post the sticky pull request comment from CI

Finally, upsertComment() searches the pull request for an existing comment containing <!-- upstash-box-visual-review -->. It updates that comment in place on new pushes or creates it on the first run, so repeated commits from a coding agent never spam the pull request thread.

Running the whole flow in GitHub Actions takes a single workflow file:

.github/workflows/visual-qa.ymlyaml
name: Visual QA
on:
  pull_request:
    types: [opened, synchronize, reopened]

jobs:
  visual-qa:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - name: Run visual QA in Upstash Box Browser
        env:
          UPSTASH_BOX_API_KEY: ${{ secrets.UPSTASH_BOX_API_KEY }}
          UPSTASH_BLOB_TOKEN: ${{ secrets.UPSTASH_BLOB_TOKEN }}
          BOX_SNAPSHOT_ID: ${{ secrets.BOX_SNAPSHOT_ID }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: npx tsx src/pr-visual-tester.ts run "${{ github.repository }}" "${{ github.event.pull_request.number }}"

What a single PR run costs

Every call in box-stages.ts records the wall-clock command time and agent spend returned by Run.cost, plus the token count from tab.act() and tab.extract().

Stage Pricing basis Cost per PR run
Box.fromSnapshot restore and dual-branch boot Active CPU only at $0.10 per CPU-hour on small ~$0.0004 for 15s of active CPU
Box Browser inspection across both branches tab.act and tab.extract token usage plus local CDP ~$0.01 for ~3,400 browser tokens
box.agent.run with ClaudeCode.Sonnet_4_5 Structured Zod verdict from the measured DOM reports ~$0.025 to $0.05 per verdict
Upstash Blob upload + GitHub comment upsert 4 annotated PNGs stored with immutable caching < $0.0001
Total per PR push box.delete() runs inside finally ~$0.035 to $0.06 total

Because box.delete() runs inside the finally block as soon as the comment is posted, there is zero idle cost between pull requests. When five coding agents push branches from their worktrees at the same time, five Boxes spin up in parallel, run their browser checks in isolation, post their screenshots to GitHub, and delete themselves in under a minute.
